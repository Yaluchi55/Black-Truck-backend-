# Black Truck backend API

A TypeScript/Express/PostgreSQL/Prisma core for the Black Truck executive ride-hailing marketplace. This is a production-oriented foundation, **not a claim that external money movement is live or regulatory approval has been completed**. Provider adapters must be integrated and certified with the selected telco/aggregator before accepting real payments.

## Included
- OTP identity flow for Zambian mobile numbers, hashed OTPs, expiry, attempts, rate limits, signed short-lived JWTs and role middleware.
- PostgreSQL schema via Prisma; PostGIS location column, trigger and GIST index via `sql/postgis.sql`.
- Socket.IO chauffeur location stream with JWT verification; Redis GEO cache and stale-location expiry.
- PostGIS nearest-driver query implementation (see note below).
- Hourly USD/ZMW refresh with configurable 2% buffer.
- Payment collection adapter, signed webhook validation, idempotent event guard, 15% platform fee accounting, 85% operator payout ledger and 48-hour minimum hold.
- Device fingerprint/network hash audit events, health endpoint and structured logging.

## Start
1. Install Node.js 22 LTS, PostgreSQL with PostGIS, and Redis.
2. `cp .env.example .env`; use strong, unique secrets and real provider credentials in your secret manager.
3. `npm install && npm run db:generate`.
4. `npx prisma migrate dev --name init` (development) or create a reviewed migration and run `npm run db:migrate` in production.
5. Run `psql "$DATABASE_URL" -f sql/postgis.sql` after migrations.
6. `npm run dev`; production uses `npm run build && npm start`.

## API
- `POST /api/auth/otp/request` `{ "phone":"+26097XXXXXXX", "role":"RIDER" }`
- `POST /api/auth/otp/verify` `{ "phone":"+26097XXXXXXX", "role":"RIDER", "code":"123456", "fullName":"..." }`
- `GET /api/forex/usd-zmw`
- `POST /api/bookings` (Bearer token; RIDER)
- `GET /api/bookings/:id` (booking owner or assigned driver)
- `POST /api/payments/collect` (Bearer token; RIDER)
- `POST /api/payments/webhook` signed provider event
- `GET /health`
- Socket.IO: chauffeur JWT in `auth.token`; events `driver:online` and `driver:location`.

## Important integration work before launch
1. **Location matching:** wire the matching query to a production endpoint and emit candidate results to the rider room; do not expose driver phone or exact location to unassigned riders. A booking dispatch state machine and reservation/locking strategy is needed to prevent two riders claiming one driver.
2. **Payment provider:** provider request/response schemas and signature format differ by aggregator. `ConfiguredPaymentProvider` uses an explicitly documented generic HMAC convention; adapt to the provider's official signing rules and raw-body requirements. Never accept unsigned callbacks. Configure mTLS/IP allowlists if provider supports them.
3. **Receipt email/PDF:** use a durable queue (BullMQ/Redis) and a maintained PDF/email provider, with retry/dead-letter handling, after the payment DB transaction commits. Add tax invoice fields and have a Zambian tax professional verify VAT/ZRA requirements. No receipt is falsely represented as sent by this core.
4. **Payout execution:** a ledger row is not a bank/mobile-money transfer. Add a separate payout worker using the provider's disbursement API, idempotency keys, reconciliation and maker-checker approval. Enforce `eligibleAt`, completed-trip thresholds, KYC and sanctions/fraud checks before releasing.
5. **Escrow/legal:** the app must not describe an internal ledger as a regulated escrow vault unless the relevant licensed arrangement exists. Obtain legal advice on Bank of Zambia payment-system requirements, consumer protection, AML/KYC and data protection.
6. **Fraud controls:** device/network matches are signals, not proof. This code hashes IP/device values and logs reuse; configure false-positive review. Never block users solely because they share carrier NAT/Wi-Fi. Device IDs must be generated by the app using a secure platform-appropriate identifier, not IMEI or other restricted hardware identifiers.
7. **Operational hardening:** secrets manager, TLS, WAF, backups/PITR, migration review, observability/alerts, SAST/dependency scanning, load tests, incident runbooks, retention policy and privacy notice are required.

## PostGIS matching query
The included `LocationService.nearbyDrivers` contains the intended indexed `ST_DWithin` approach, but its optional vehicle-tier branch is deliberately not wired as a string fragment. Replace that method with two static parameterized query branches (tier/no tier) before enabling matching; never concatenate client-provided SQL. This safety note is explicit so an incomplete path is not mistaken for a finished endpoint.

## Financial rules
- Commission: 15% of confirmed gross collection; operator ledger: 85%.
- Any gross transaction above K2,000 is held for at least 48 hours. The configured hold duration cannot be set below 48 hours.
- Payout execution must additionally verify completed trips and account/fraud status; no automated disbursement is implemented until the provider-specific worker is added.
